# AURA demo video — 2 minutes 40 seconds

Record the real app running on the laptop. Keep the final video under three minutes. Speak clearly, use no copyrighted music, and do not edit in an answer the app did not produce.

## Before recording

- Open **http://localhost:8006** and wait until the AURA page is ready.
- Grant camera and microphone permission before you start recording.
- Put a familiar object, such as keys or earbuds, clearly in view. Keep the scene free of private papers, faces, and personal location information.
- Set English for the demo. Confirm the local model and the laptop speaking voice work.
- Start the screen recording only after the permissions and setup are complete. Leave the app's “Alexa+ web simulation” label visible.

## Exact walkthrough

### 0:00–0:20 — Introduce the problem

**Show:** AURA home screen and the “Alexa+ web simulation” label.

**Say:** “Finding everyday objects can be frustrating when you can’t rely on a screen. AURA is a voice-first visual companion that helps people with low vision explore what is in front of them. This entry uses the Alexa+ web-simulation path; it is not a live Alexa or Echo integration.”

### 0:20–0:55 — Ask what is in view

**Show:** Live camera view and AURA listening indicator.

**Say to AURA:** “Sam, what is in front of me?”

Let the real spoken answer finish. Show the route status and visible scene. Do not cut away before the result.

### 0:55–1:40 — Find a named object hands-free

**Show:** Keep the object in the camera frame. Do not type in the Find an item box.

**Say to AURA:** “Sam, find my keys.”

Let the answer finish. Move the camera to a different angle.

**Say to AURA:** “Sam, look again.”

Let the second answer finish. AURA should describe visible evidence and a frame position; it should not claim an exact distance. If the wake word fails during your rehearsal, fix it before recording rather than adding a fake response.

### 1:40–2:00 — Show the companion interaction

**Say to AURA:** “I’m feeling overwhelmed. Can you listen for a moment?”

Let the spoken response play.

**Say:** “AURA offers supportive conversation, but it is not a therapist or emergency service.”

### 2:00–2:25 — Explain privacy and limitations

**Show:** The local-processing note and the language selector.

**Say:** “Speech recognition runs locally on this laptop. The camera stays live in the browser, and a recent frame is sent to the local vision model only for a visual question. The camera cannot measure heat or exact distance, and the model can make mistakes.”

### 2:25–2:40 — Close

**Show:** Return to the live AURA screen.

**Say:** “AURA turns a spoken request into a visual check and a spoken reply, with a hands-free scan follow-up. This is a working prototype, and we are measuring its recognition, response time, and accessibility with real trials.”

## If something fails

- If the camera answer is unreliable, rehearse with a larger, well-lit object and a steady frame.
- If voice recognition fails, use only the fallback actually supported by the running app and describe it honestly. Never add a generated or staged answer.
- If the voice demo is still unreliable, record a shorter video showing the real **Describe view** action and state that hands-free voice is a prototype limitation.
- Leave the heart-rate/SOS card out of this video unless there is time to show it clearly as a simulation. It does not measure health or contact anyone.
